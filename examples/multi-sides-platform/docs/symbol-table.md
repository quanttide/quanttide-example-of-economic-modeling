# 符号定义表

> 本文档对照 Lean 代码与经济学直觉，帮助理解形式化模型中的每个符号。
> 业务场景：结果交付型城际出行平台——用户告知出行目的，平台推荐商家并给出最大优惠。

---

## 参数（ModelParams）

参数是模型的外部输入——由数据估计或政策设定，均衡内部不决定它们。

| 符号 | 代码名称 | 类型 | 经济学含义 | 业务直觉 |
|:----:|:---------|:----:|-----------|----------|
| \(A\) | `A` | ℝ | **基础出行需求** | 即使没有商家入驻、平台不补贴，每天也有 A 个人需要从 A 城到 B 城 |
| \(M\) | `M` | ℝ | **市场总人口上限** | 两城之间每天最多只有 M 个人出行，受人口/运力上限约束 |
| \(B\) | `B` | ℝ | **基础入驻意愿** | 即使没有用户、平台不收钱，也有 B 个商家愿意入驻 |
| \(\alpha\) | `α` | ℝ | **用户价格敏感度** | 用户涨价 1 元，出行量减少 α 人；敏感度越高，平台越不敢涨价 |
| \(\beta\) | `β` | ℝ | **商家→用户的交叉网络效应** | 每多 1 个商家入驻，出行量增加 β 人。商家越多，用户越愿意来（如更多餐厅可选） |
| \(\gamma\) | `γ` | ℝ | **用户→商家的交叉网络效应** | 每多 1 个用户出行，入驻商家数增加 γ。用户越多，商家越愿意入驻（如可见的客流） |
| \(\delta_f\) | `δ_f` | ℝ | **商家对流量费的价格敏感度** | 流量费涨 1 元，入驻商家减少 δ_f 个。敏感度越高，平台越不敢收流量费 |
| \(\delta_l\) | `δ_l` | ℝ | **商家对入驻费的价格敏感度** | 入驻费涨 1 元，入驻商家减少 δ_l 个 |
| \(c\) | `c` | ℝ | **出行技术成本** | 每趟出行的司机油费/车辆折旧等刚性成本，平台必须覆盖 |

### 参数约束

```
α > 0      用户总是对涨价敏感（否则涨价不会减少需求）
γ ≥ 0      用户量不会"吓跑"商家（γ=0 时用户量不影响入驻）
δ_f ≥ 0    流量费不会"吸引"商家入驻
δ_l ≥ 0    同理
βγ ≠ 1    这是技术性条件——当 βγ=1 时网络效应形成完美闭环→Q,N 对价格响应无穷大→无均衡
```

## 内生变量（ModelVars）

内生变量是模型要**求解**的值——均衡时这些变量取什么值由所有条件共同决定。

| 符号 | 代码名称 | 边界 | 经济学含义 | 业务直觉 |
|:----:|:---------|:----:|-----------|----------|
| \(p_u\) | `pu` | free | **用户支付价格** | 用户每趟出行的票价。可为正（平台赚钱）、零（免费）、负（平台补贴，即倒贴钱给用户乘车） |
| \(p_f\) | `pf` | ≥ 0 | **按流量收费** | 商家每被推荐一趟出行，付给平台 p_f 元。类似于美团的按订单抽成 |
| \(p_l\) | `pl` | ≥ 0 | **按入驻收费** | 商家每入驻一期（月/年），付给平台 p_l 元。类似于商场柜台费 |
| \(Q\) | `Q` | 0 ≤ Q ≤ M | **出行量** | 每天实际发生的从 A 城到 B 城的出行趟数 |
| \(N\) | `N` | ≥ 0 | **入驻商家数** | 在平台上注册并接受推荐的目的地商家数量 |

### Q 的市场规模上限

`0 ≤ Q ≤ M` 是关键约束——出行量不可能超过城市间的人口/运力上限。

- 当 Q < M 时：平台还有增长空间
- 当 Q = M 时：**市场饱和**，平台只能靠提高客单价或商家收费来增收

## 行为方程

行为方程描述用户和商家**各自**如何响应价格和网络效应。

### 用户需求方程 `demand_eq`

```lean
def demand_eq (p : ModelParams) (v : ModelVars) : Prop :=
  v.Q = p.A - p.α * v.pu + p.β * v.N
```

```
Q = A - α·p_u + β·N

↑     ↑      ↑         ↑
出行量 基础  涨价会    商家越多
      需求  减少需求  用户越愿意来
```

**直觉**：
- 涨价 1 元 → 出行量减少 α 人（用户心疼钱）
- 多 1 个商家入驻 → 出行量增加 β 人（更多选择吸引更多用户）
- 当平台补贴（p_u < 0）时，`-α·p_u` 变成**正数**，出行量高于 A + β·N

### 商家入驻方程 `entry_eq`

```lean
def entry_eq (p : ModelParams) (v : ModelVars) : Prop :=
  v.N = p.B + p.γ * v.Q - p.δ_f * v.pf - p.δ_l * v.pl
```

```
N = B + γ·Q - δ_f·p_f - δ_l·p_l

↑     ↑    ↑         ↑            ↑
入驻  基础  用户多    流量费涨     入驻费涨
商家数 意愿  商家越愿  商家越不愿   商家越不愿
            意入驻    意入驻       意入驻
```

**直觉**：
- 多 1 个用户出行 → 入驻商家增加 γ 个（客流吸引商家）
- 流量费涨 1 元 → 入驻商家减少 δ_f 个（商家心疼每次的抽成）
- 入驻费涨 1 元 → 入驻商家减少 δ_l 个（商家心疼固定成本）

## 均衡条件（Equilibrium）

均衡是**所有条件同时成立**的状态——没有任何参与者想单方面改变自己的决策。

### MCP 互补条件

Lean 代码用以下结构表达均衡：

```lean
structure Equilibrium (p : ModelParams) where
  vars      : ModelVars     -- 一组变量取值
  h_demand  : demand_eq p vars     -- ① 用户需求实现
  h_entry   : entry_eq p vars      -- ② 商家入驻实现
  h_pf_nonneg : 0 ≤ vars.pf        -- 流量费不能为负
  h_pl_nonneg : 0 ≤ vars.pl        -- 入驻费不能为负
  h_N_nonneg  : 0 ≤ vars.N
  h_Q_nonneg  : 0 ≤ vars.Q
  h_Q_upper   : vars.Q ≤ p.M       -- ③ 市场容量约束
  h_foc_pu    : foc_pu_cond ...    -- ④ 平台定价最优
  h_foc_pf    : foc_pf_cond ...
  h_foc_pl    : foc_pl_cond ...
```

| 条件 | 含义 | 通俗理解 |
|:----:|------|----------|
| ① 需求实现 | 用户确实按需求方程出行了 | 给定票价 p_u 和商家数 N，出行量 Q 由用户的选择决定 |
| ② 入驻实现 | 商家确实按入驻方程入驻了 | 给定流量费 p_f、入驻费 p_l 和用户数 Q，商家数 N 由商家的选择决定 |
| ③ 容量约束 | 出行量不超过市场总人口 | 平台再补贴也不会有人口之外的出行需求 |
| ④ 平台最优 | 平台在当前价格下利润最高 | 平台试过涨价/降价/调整商家收费，发现当前定价是"最佳"的 |

## 闭环理解：Q 和 N 如何通过价格联动

这是理解模型最核心的一步。看这张因果图：

```
p_u ──→ Q ──→ N
 ↑             │
 └────── β ←───┘
 
p_f ──→ N ──→ Q
 ↑             │
 └────── γ ←───┘
```

**正向环路**（自我增强）：
- p_u 下降 → Q 上升 → N 上升（γ）→ Q 进一步上升（β）→ ...

**负向环路**（自我抑制）：
- p_f 上升 → N 下降 → Q 下降（β）→ N 进一步下降（γ）→ ...

### 闭式解的直觉

`Q_of_p` 和 `N_of_p` 把这种循环反馈"解开"为价格的直接函数：

```lean
def Q_of_p (p : ModelParams) (pu pf pl : ℝ) : ℝ :=
  (A - α·pu + β·(B - δ_f·pf - δ_l·pl)) / (1 - β·γ)

def N_of_p (p : ModelParams) (pu pf pl : ℝ) : ℝ :=
  (B - δ_f·pf - δ_l·pl + γ·(A - α·pu)) / (1 - β·γ)
```

**分母 `1 - βγ` 的经济含义**：

| βγ 的范围 | 含义 | 业务场景 |
|:----------|------|----------|
| βγ = 0 | 无网络效应（γ=0 或 β=0） | 出行量与商家数互不影响 |
| 0 < βγ < 1 | 弱网络效应，有唯一均衡 | 最常见——网络效应存在但不会无限放大 |
| βγ = 1 | **临界值**，分母为零 | 网络效应完美闭环，Q 对价格无限敏感——模型在此处退化 |
| βγ > 1 | 强网络效应，可能多均衡 | 用户越多→商家越多→用户更多，可能"赢家通吃" |

## FOC 条件解析

平台利润：

```
π = (p_u - c)·Q + p_f·N·Q + p_l·N

    客运收入      流量费收入     入驻费收入
    (可能为负)     (按效果)      (固定)
```

平台选择 p_u, p_f, p_l 最大化 π——但知道 Q 和 N 会通过行为方程响应价格变化。

利用 `Q_of_p` 和 `N_of_p`，π 成为**仅依赖价格**的函数（Q,N 已被消去）：

```lean
def π (p : ModelParams) (pu pf pl : ℝ) : ℝ :=
  let Q := Q_of_p p pu pf pl
  let N := N_of_p p pu pf pl
  (pu - p.c) * Q + pf * N * Q + pl * N
```

对 π(pu, pf, pl) 求偏导即可得到 FOC，此时已自然包含所有交叉反馈——因为 Q,N 已展开为价格的显式函数。

例如 ∂π/∂pu 的完整形式：

```
∂π/∂pu = Q + (p_u - c + p_f·N)·(∂Q/∂pu) + p_f·Q·(∂N/∂pu) + p_l·(∂N/∂pu) = 0

          ↑              ↑                       ↑                ↑
        直接效应      间接效应                间接效应          间接效应
        （多卖一       （涨价后 Q            （涨价后 Q          （涨价后 N
        张票的收       下降，影响客运        下降，影响流量      下降，影响入驻
        入变化）        和流量收入）          费收入）             费收入）
```

## 几个关键概念的直觉

### "免费出行" (free_ride) 何时出现？

`p_u ≤ 0` 意味着平台贴钱给用户坐车。这在传统行业看似亏本，但在三边市场中可能最优：

- p_u 为负 → Q 大幅上升（绝对值 `α·p_u` 变成正贡献）
- Q 上升 → N 上升（商家被客流吸引）
- N 上升 → Q 进一步上升（更多商家吸引更多用户）
- **最终**：平台在流量费和入驻费上赚的钱，超过了补贴用户的损失

临界条件 `β·γ > α` 的直觉：
- βγ > α：网络效应的闭环放大能力 > 用户的价格敏感度。此时补贴一个用户能"撬动"足够多的商家收入来覆盖成本
- βγ ≤ α：补贴用户带来的额外网络效应不足以弥补票价损失，平台应该收正价

### "市场饱和" (market_saturated) 意味着什么？

Q = M 表示出行量碰到了人口/运力的天花板。此时：
- 再降价也不能增加 Q（被 M 卡住）
- 平台只能靠提高商家收费来增收
- 这是分析平台"增长天花板"的关键临界点
